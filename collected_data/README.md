# Collected Data — Inventory for Fresh-Start Approach

Every data file found across the project (excluding `venv/`, `.git/`), organized by provenance. Nothing has been cleaned, deduped, or merged yet — this is the raw inventory to work from for the new approach.

## Folders

- **`main_checkout/`** — original files as they exist on `main`, before any of the foundations-fix work. This is the ground truth for "what raw data do we actually have," including the untouched `references/*.xlsx` source spreadsheets, the original scanned/hand-georeferenced `gis_data/*.tif`, and everything under `scratch/` (regional indexed CSVs, road shapefile, alternate physical-feature extracts) that was never committed to git.
- **`worktree_task2_corrected/`** — the subset of files touched by the (separate, still-unmerged) foundations-fix branch, specifically: the 8 physical rasters with the coastline-calibrated registration fix applied (`registration_offset.json` documents the measured offset — IoU 0.81→0.91, ~24.85km correction), plus the rebuilt Phase 1 feature/label CSVs and the two `_PRE_CALIBRATION` renamed highway/piste rasters (kept for reference, not for reuse — they're still misregistered by ~25km relative to the other 8). Kept separately since the *raster registration methodology* wasn't in question — only the labeling/modeling approach was.

## Known data-quality findings (found while diagnosing the "only 1 Facile site" anomaly)

- **Cap Malabata**: coordinate is corrupted at the source — `main_checkout/livrable/phase1_national_accessibility/data/geosites_coordinates_clean.csv` and `main_checkout/livrable/phase2_regional_analytics/data/geosites_ttah_indexed.csv` both store `lon=-0.0333`, which is nowhere near Morocco (real Cap Malabata, near Tangier). **The Phase 2 report (`geosite_phase2_report_fr.tex:101`) documents the correct value: `-5.7133°W`** — this was already found and fixed once, at the report-text level, but never propagated back into any data CSV, so every downstream pipeline run (including the OSRM-label rebuild) re-inherited the bad coordinate.
- **Ras Ma Spring** (likely "Ras El Ma"): **correct-looking coordinates exist** in `main_checkout/livrable/phase2_regional_analytics/data/geosites_ttah_indexed.csv` (lat 35.218, lon -5.319, Rif/TTAH region, labeled Facile) — but this site is **absent from the national catalog** (`geosites_coordinates_clean.csv`, 780 rows) entirely. Also appears in `references/Data Classification_Geoheritage.xlsx` as "Ras Ma Spring" with coordinates in an unparsed/malformed format (`513050N` / `507250W`) never converted to decimal degrees. **Complication:** the Phase 2 report's own sample table (`geosite_phase2_report_fr.tex:136`) lists a *different* site, "Source Ras El Ma," at `(35.1689, -5.2606)` — coordinates that don't match "Ras Ma Spring" in the CSV. Either these are two distinct real sites, or the report table was hand-typed/stale and drifted from the underlying data (the same failure mode independently found and fixed in the Phase 1 report during the foundations-fix branch — see `full-review.md`). Needs resolving before either coordinate is trusted as ground truth.
- **Fahs-Anjra**: not a named catalog entry at all — it's a **coordinate-based field validation point** from the Phase 2 report (`geosite_phase2_report_fr.tex:289`, repère (2) in Figures 10/11): at `(35.7250°N, -5.6685°W)`, the national model predicted Difficile (slope 11.9°), but route verification showed the point is <750m / 11 min walk from **Gare de Melloussa**, and the regional TTAH model correctly reclassified it Facile. This is a real, already-verified ground-truth label — just never entered into any geosite CSV as a named site with a category.
- **Punta Cires** ("The flute casts of Punta Cires"): **is** in `geosites_ttah_indexed.csv` (row 645, `35.9, -5.4167`) but stored there as **Difficile (score 0.2077)** — the *national* score. The Phase 2 report (`geosite_phase2_report_fr.tex:290`) describes a separate, already-done ground-truth verification (8 min / 2.7km drive via piste from Belyounech vs. 1h05 on foot) that reclassifies it **Facile**, but that correction was never written back into the CSV's label column — it exists only as report prose.
- **Oulmès/Khouribga plateau** (BMK, `33.4720°N, -6.9462°W`, repère (1) in `geosite_phase2_report_fr.tex:291`): the *opposite* case — the national model said Difficile, the regional BMK model reclassified it Facile based on flat terrain (slope 1.8°), but the report itself flags this as likely an **overestimate**, since there's no paved road nearby — a caution against relying on terrain alone without transportation infrastructure context.

**These four report-documented points (Fahs-Anjra/Melloussa, Punta Cires, Oulmès/Khouribga, plus the Cap Malabata coordinate fix) are already-verified, real-world accessibility ground truth** — exactly the kind of expert-validated anchor the new labeling protocol needs, and they predate this session. They should be treated as authoritative reference points for validating whatever new approach comes next, alongside whatever additional sites you label yourself.

These findings also suggest the national catalog (`geosites_coordinates_clean.csv`) is not simply a superset of the regional catalogs (`geosites_ttah_indexed.csv`, `geosites_bmk_indexed.csv`) — cross-referencing all three against each other, plus the two Phase 2 report's field-verification callouts, is likely to surface more sites like these.
